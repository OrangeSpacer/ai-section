# System Design: BI Dashboard

## Описание

Ты разрабатываешь frontend для BI-системы на React.

Backend полностью управляет конфигурацией дашбордов: определяет набор графиков, их типы, настройки и доступные фильтры.

Frontend должен динамически строить интерфейс на основе полученной конфигурации и обеспечивать взаимодействие между фильтрами и графиками.

### Пример конфигурации

```json
{
  "charts": [
    {
      "id": "1",
      "type": "line",
      "title": "Sales",
      "data": [],
      "config": {}
    },
    {
      "id": "2",
      "type": "bar",
      "title": "Revenue",
      "data": [],
      "config": {}
    }
  ],
  "filters": [
    {
      "id": "date",
      "type": "date_range",
      "label": "Дата"
    },
    {
      "id": "region",
      "type": "select",
      "label": "Регион",
      "options": ["EU", "US"]
    }
  ]
}
```

## Задача

Спроектировать frontend-архитектуру, которая удовлетворяет следующим требованиям.

### 1. Динамический рендеринг графиков

- Графики создаются на основании конфигурации backend.
- Тип графика определяется полем `type`.
- Каждый тип графика может иметь собственную структуру данных и настройки.
- Неизвестные или неподдерживаемые типы не должны приводить к падению всего дашборда.

### 2. Расширяемость

- Система должна позволять добавлять новые типы графиков.
- Добавление нового типа не должно требовать переписывания основного механизма рендеринга.
- Разные команды должны иметь возможность независимо разрабатывать новые типы графиков.

### 3. Работа с фильтрами

- Фильтры динамически создаются на основании конфигурации backend.
- Система должна поддерживать разные типы фильтров, например `select` и `date_range`.
- Пользователь может изменять значения фильтров.
- Один фильтр может влиять на несколько графиков.

### 4. Синхронизация фильтров и графиков

- При изменении фильтра должны обновляться связанные с ним графики.
- Графики, не зависящие от изменённого фильтра, не должны выполнять лишние запросы.
- Необходимо предусмотреть загрузку данных графиков с backend с учётом выбранных фильтров.

### 5. Управление состоянием

- Необходимо определить, где хранится конфигурация дашборда.
- Где и как хранятся выбранные значения фильтров.
- Как организовано состояние отдельных графиков.
- Как компоненты взаимодействуют между собой.

## Дополнительные условия

При проектировании учитывай, что в дальнейшем система может поддерживать десятки типов графиков, большое количество фильтров и дашборды с сотнями виджетов.

Архитектура должна оставаться расширяемой и удобной для сопровождения.
